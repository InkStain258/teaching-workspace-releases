备题达 产品文档（全学科 · 全学段版）

版本 1.3.3　|　平台 Windows 10 / 11 桌面版

本文是按模块组织的产品文档：每个模块讲清它的位置、作用、页面构成、数据来源、操作路径和输出，再补全局能力与设置项。查具体功能看第二章起，想先了解整体看第一章。

一、产品是什么

1.1 一句话

备题达是一个本地优先的全学科教学工作台：把备课、出题、讲评、记忆管理放在一处，数据存在本机，离线可用。

它做的四件事：备课（教参 → 教案）、出题（题库 → 卷子）、讲评（成绩 → 薄弱点）、记忆（卡片 → 间隔复习）。

它不做的事，写在第十章。

1.2 日常三类活，分别落在哪几个模块

你要做的事 主要模块 配套模块
备一节课 备课中心 教材教参、题库（课内对接）、单元教学
出一份卷 题库 → 组卷台 专项训练、学情与讲评
考完讲评 学情与讲评 题库（原题回看）、组卷台（投影）

1.3 界面骨架

区域 说明
顶栏 左侧产品名与版本，右上角「设置」
侧栏 三组导航，见 1.4
内容区 当前模块的页面
组卷篮抽屉 右侧滑出（Ctrl + B），跨页面累积选题
助手面板 右下角，AI 对话，能读当前页面的上下文
托盘 关窗不退出，程序留在任务栏托盘

1.4 侧栏结构

分组 模块 用在什么时候
备课 工作台、备课中心、单元结构导入、单元教学、教材教参、导学案、校历 上课之前：找内容、写教案、排课时
题库与出题 题库、学情与讲评、组卷台、专项训练、记忆模块 出卷、练卷、考后讲评
资料与帮助 数据与备份、素材库、使用说明 导入素材、备份数据、查说明

这一版不绑定学科与学段：册次、单元、题型的叫法都用通用词（「教学内容」而不是「课文」）。零预置数据——第一次用需要自己导入内容。

1.5 全局能力

能力 说明
命令面板 Ctrl + K 或 /，搜页面名、教学内容、题目、考点，Enter 打开
组卷篮 Ctrl + B 开关抽屉，跨页面保留，题以「ref」标识
投影讲评模式 全屏逐题，← → 翻题，空格 揭示答案与解析
导出 试卷与教案导出 .docx，版式已排好，Word 里微调即可
撤销 普通写操作 Ctrl + Z 撤销
更新检查 启动时检查，有新版提示；「更新日志」看历次改动

二、模块参考 · 备课

2.1 工作台
位置 侧栏 → 备课 → 工作台
作用 打开应用后的第一屏：进度、待办、最近改动
页面构成 概览卡片组 + 快捷入口

数据来源：教学进度（校历与单元安排）、最近打开记录、组卷篮状态。

2.2 备课中心
位置 侧栏 → 备课 → 备课中心
作用 一次课从看要点到教案成稿，全在这一页
页面构成 顶部册次/内容选择器 + 左「教参要点」/ 中「展·探·练教案」/ 右「课内对接题目」

数据来源：教材教参（你自己导入的课时条目）+ 题库（课内对接的题）。

操作路径：选择教学内容 → 改教案骨架 → 课内对接/当堂检测 → 导出 .docx

三栏各自干什么：

  • 左：这次课的要点，用来判断重点落在哪。
  • 中：教案骨架按「导入 — 展开 — 探究 — 练习」四段排。
  • 右：把题库里对得上的题挂进对应环节。

输出：教案 .docx；课内对接部分可进「投影讲评模式」当堂讲。

注意：选择器里选不到东西，说明内容库还是空的，先去 2.3 导入。

2.3 单元结构导入
位置 侧栏 → 备课 → 单元结构导入
作用 批量建立课程结构（单元 → 教学内容）
页面构成 粘贴区 + 预览 + 导入

输入格式：一行一条。单元名单独一行，条目写成「1 集合的含义与表示」，序号自动识别。

册次命名由你定：「上册」「必修一」「模块一」都行，后续筛选按这个走。建议一套命名从头用到尾，中途换会分裂成两组。

注意：导入是新建，不覆盖。重复导入同一册会出现两份结构。

2.4 单元教学
位置 侧栏 → 备课 → 单元教学
作用 以单元为单位看整体安排
页面构成 单元目标、课时分配、读写任务、作业配置

操作路径：看单元目标与课时 → 逐课备课 → 单元检测组卷 → 导出单元设计

2.5 教材教参
位置 侧栏 → 备课 → 教材教参
作用 自己导入的课时条目 + 教参解读，可关联题目
页面构成 检索栏（名称/册次/单元）+ 条目列表 + 详情

数据来源：你自己导入的内容，无预置数据。所以这一页的价值取决于导入了多少——建议一次导一个学期，不要零散加。

用法：备课时查这次课有什么现成材料；或按册次、单元批量看。

2.6 导学案
位置 侧栏 → 备课 → 导学案
作用 用一套模板走完一次课：预学、探究、当堂检测、作业
页面构成 四段式编辑区 + 选题入口

两种用法：

  • 从零写：选教学内容，按四段填。
  • 挂现成题：当堂检测与作业两段直接从题库选题。

输出：.docx，版式已排好。

关联：题来自 3.1；内容来自 2.5。

2.7 校历
位置 侧栏 → 备课 → 校历
作用 课表与日程
页面构成 月 / 周 / 日三种视图 + 日程编辑

数据来源：先在设置里定学期起止，再按周排。

能记什么：课表、公开课、考试、调课、教研活动。

关联：MCP 的 calendar_get / event_add 读写这份数据。

2.8 知识点
位置 侧栏 → 备课 → 知识点
作用 知识点的分类视图与题量分布
页面构成 知识点树 + 题量统计 + 双向细目

数据来源：题库里的题按知识点归类。

与题库的分工：题库是检索视图（按条件找题），知识点是分类视图（看结构、看分布）。两边同源。

用法：出卷前看主干考点分布，或做双向细目表。

三、模块参考 · 题库与出题

3.1 题库
位置 侧栏 → 题库与出题 → 题库
作用 全库检索与选题入口
页面构成 筛选区 + 结果列表 + 单题详情

数据来源：初始为空。两条进数据的路：

  1. 素材库导入：上传 Word、PDF、图片，或粘贴文本，系统自动切分成题。
  2. JSON 导入：结构化数据用，模板见「素材库 → 接口设置」。

筛选维度：年份、卷别、地区、考点、题型、难度、关键词。

操作路径：筛选题目 → 加入组卷篮（本页） → 组卷台 → 导出 .docx

单题能看：题干、选项、答案、解析。可单题投影。

3.2 组卷台
位置 侧栏 → 题库与出题 → 组卷台
作用 把组卷篮里的题排成一份可导出的卷子
页面构成 卷头设置 + 题目列表（可排序调分）+ 导出选项

操作路径：选题 → 组卷（本页） → 导出 Word → 打印/投影

自动完成的三件事：题号编号、分值统计、双向细目表。

可调项：题序、每题分值、是否附答案、是否附细目表、卷头字段。

输出：.docx；或直接进「投影讲评模式」。

3.3 专项训练
位置 侧栏 → 题库与出题 → 专项训练
作用 单考点抽题，生成小练卷
页面构成 考点选择 + 题量 + 预览

操作路径：选考点（本页） → 抽题 → 导出 .docx / 投影 → 送组卷台

与组卷台的区别：组卷台做整卷，专项训练做单点突破。

3.4 记忆模块
位置 侧栏 → 题库与出题 → 记忆模块
作用 自建卡片 + 间隔复习
页面构成 分类列表 + 卡片列表 + 复习界面

复习节奏：答对升一级（0 → 1 → 3 → 7 天），答错退回第一天。

默认分类：概念、公式、必背原文（可增删）。

建卡两种方式：单张录入；批量粘贴（一段文本一次切多张）。

关联：MCP 的 memory_list / memory_add 读写这份数据。

3.5 学情与讲评
位置 侧栏 → 题库与出题 → 学情与讲评
作用 考后看数据，定讲评重点
页面构成 成绩录入 + 得分率 + 错题清单 + 薄弱考点

数据来源：你录入的考试成绩 + 题目与考点的对应关系。

错题回看：错题能回挂到题库原题，讲评时点开就是原题与解析。

四、模块参考 · 资料与帮助

4.1 素材库
位置 侧栏 → 资料与帮助 → 素材库
作用 零门槛导入外部材料，并为导入接口提供设置入口
页面构成 上传区、分类归档列表、接口设置

数据来源：你自己上传的文件。存储在本地 IndexedDB，不受 localStorage 5 MB 限制，图片量大也放得下。

能导入什么：文字（直接粘贴）、Word、图片、PDF。系统按内容自动归类。

接口设置：篇目与试卷的批量导入入口也在这里，含 JSON 模板。格式见附录 B。

关联：导入的教学内容进教材教参，导入的题进题库。

4.2 数据与备份
位置 侧栏 → 资料与帮助 → 数据与备份
作用 导出/导入全量数据，换机与防丢
页面构成 导出备份、导入恢复、缓存位置

数据在哪：全部存在本机。localStorage 存配置与结构化数据，IndexedDB 存素材与题索引。都不上传服务器。

三个动作：

  • 导出备份：打包成 JSON。建议每周一次，或大改题库之前一次。
  • 导入恢复：选备份文件覆盖当前数据，导入前有提示。
  • 缓存位置：显示实际磁盘路径，可直接复制到资源管理器。

注意：备份不含 AI 接口 Key 与 ima 凭据，换机后要重填。

4.3 使用说明

应用内的简版说明：五分钟上手、功能一览、快捷键、数据来源。适合刚装好时看一遍。

4.4 插件与外观 / 更新日志

  • 插件与外观：装插件、调外观。插件可往侧栏加页面、往命令面板加命令。
  • 更新日志：按版本倒序，每个版本改了什么。装新版后首次打开会弹一次本次更新。

五、设置

「设置」有五个分页，都存在本机。

5.1 卷头信息

学校、学科、年级、班级、学期、姓名。

导出的试卷与教案自动带上这几行。某项留空，那一行不打印——不需要的项直接空着，比事后在 Word 里删省事。

5.2 AI 接口

项 说明
接口地址 以 /v1 结尾，如 https://api.deepseek.com/v1 或本机网关 http://127.0.0.1:3425/v1
Key 只存本机，不进备份、不上传
模型 接口支持的模型名
协议 chat/completions（多数服务）或 responses（新接口/网关）
推理强度 推理型模型选「不推理」，否则输出额度常被思考过程吃掉

填完点「测试」，能返回一句话即为连通。

5.3 外观

浅色 / 纸本 / 深色 / 跟随系统。即时生效，不改数据。

5.4 ima 知识库

填 ima 的连接凭据。配好之后：应用内的 ima 检索可用，MCP 的 ima_* 四个工具也可用。不配不影响其他功能。

5.5 MCP

端口、令牌、写操作开关、连接状态。详见第七章。

六、AI 助手
位置 右下角助手面板
作用 在页面上下文里做加工：整理、改写、出题、分析
数据来源 当前页面的状态（正在看哪一课、筛了什么、组卷篮几道题）+ 你的提问

能读到的上下文：当前模块、选中的教学内容、题库筛选条件、组卷篮内容、记忆分类。所以直接说「按这个考点补两道题」它就知道「这个」指什么。

四类典型用法：

  • 备课：把教参要点压成三段、按展探练写教案骨架
  • 出题：按 45 分出卷、补一道 6 分主观题、把这题改成选择题
  • 讲评：按得分率分析薄弱考点、生成讲评提纲
  • 记忆：把一段文本整理成卡片

写操作要确认：AI 要往题库、组卷篮、记忆模块写东西时，先出待确认卡片，写明改什么，你点「执行」才落盘。写完可 Ctrl + Z 撤销。

七、MCP 服务器（对外接口）

前六章讲应用内的模块。这一章讲对外接口：让应用外的 AI 客户端直接读写库里的数据。

7.1 定位与边界
它是什么 内置在本地的 MCP 服务器，把工作台的能力暴露成 23 个工具
监听 只监听 127.0.0.1，局域网与公网都连不进来
依赖 应用必须开着。数据在窗口里，窗口不在服务就没有意义
与 AI 接口的区别 AI 接口是「应用内调模型」，MCP 是「外部客户端调应用」

7.2 开启、端口与令牌

  1. 「设置 → MCP」，确认顶部显示服务运行中（默认随应用启动）。
  2. 复制「带令牌的地址」。
  3. 粘进客户端。

地址形如：

http://127.0.0.1:47321/mcp?token=你的令牌

端口可在面板改，改完保存。令牌是 32 位十六进制随机串，只存本机。可点「重新生成令牌」，旧令牌立刻失效。

令牌两种传法都认：URL 里的 ?token=，或请求头 Authorization: Bearer 你的令牌。/health 免令牌，用来确认服务活着。

7.3 写操作开关

面板上「允许 AI 直接写入（跳过确认）」勾选框，默认关。

  • 关：写请求不落库，只在窗口出待确认卡片，你点了才写。
  • 开：直接执行，可 Ctrl + Z 撤销。

写工具只有 6 个，其余都是读；读不受开关影响。

7.4 客户端配置

要填的只有两样：地址、令牌。格式各家不同。

Claude Desktop — %APPDATA%\Claude\claude_desktop_config.json：

{
  "mcpServers": {
    "petita": {
      "type": "http",
      "url": "http://127.0.0.1:47321/mcp?token=你的令牌"
    }
  }
}

保存后完全退出（含托盘），再启动。

Cursor — 项目级 <项目>/.cursor/mcp.json，全局 ~/.cursor/mcp.json，格式同上。

VS Code（GitHub Copilot Chat） — .vscode/mcp.json，键名从 mcpServers 换成 servers：

{
  "servers": {
    "petita": { "type": "http", "url": "http://127.0.0.1:47321/mcp?token=你的令牌" }
  }
}

Claude Code：

claude mcp add --transport http petita "http://127.0.0.1:47321/mcp?token=你的令牌"
claude mcp list

WorkBuddy — C:\Users\<用户名>\.workbuddy\mcp.json。该文件里通常已有其他服务器，往 mcpServers 里加一段：

{
  "mcpServers": {
    "petita": {
      "type": "http",
      "url": "http://127.0.0.1:47321/mcp",
      "headers": { "Authorization": "Bearer 你的令牌" },
      "timeout": 30000
    }
  }
}

三点：

  • type 写 http；若不认，改 streamable-http 再试。
  • WorkBuddy 的条目习惯把令牌放 headers 而不是 URL，上面这样写是为与你已有条目一致。
  • 改完重启 WorkBuddy，它在启动时读一次配置。

Cherry Studio — 设置 → MCP 服务器 → 添加，类型 streamableHttp，URL 填带令牌地址。

Cline — 设置 → MCP Servers → Remote Servers，填名称与 URL，只认 http 类型。

Continue — ~/.continue/config.json：

{
  "mcpServers": [
    { "name": "petita",
      "transport": { "type": "http", "url": "http://127.0.0.1:47321/mcp?token=你的令牌" } }
  ]
}

自建平台（Open WebUI、LibreChat 等） — 配置项名称各异，核心是 URL。要求单独填 Header 的，填 Authorization: Bearer 你的令牌，URL 里的 ?token= 去掉。

只支持命令行的客户端 — 需要一个 stdio → HTTP 的桥：

#!/usr/bin/env node
// stdio → HTTP 桥：把客户端 stdin 的每行转发给备题达
const readline = require("readline");
const URL = process.env.PETITA_URL || "http://127.0.0.1:47321/mcp?token=你的令牌";

readline.createInterface({ input: process.stdin }).on("line", async (line) => {
  if (!line.trim()) return;
  try {
    const res = await fetch(URL, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: line,
    });
    process.stdout.write((await res.text()).trim() + "\n");
  } catch (e) {
    process.stdout.write(JSON.stringify({
      jsonrpc: "2.0", id: null, error: { code: -32000, message: String(e) }
    }) + "\n");
  }
});

存成 petita-bridge.js，客户端里 command 填 node，参数填文件路径。

自己写 agent — 不需要 SDK：

BASE="http://127.0.0.1:47321/mcp?token=你的令牌"

curl -s "$BASE" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"my-agent","version":"0.1"}}}'

curl -s "$BASE" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'

curl -s "$BASE" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"bank_stats","arguments":{}}}'

initialize 必须第一个发；之后每次请求都是独立 POST，无会话 cookie。

7.5 不想手动配：把这份文档发给 AI

配 JSON 对不熟悉的人来说是个坎。更省事的办法是让 AI 替你配。

把这份文档（安装目录 docs\产品文档.md，或官网这一页）整段发给任意一个能改文件的 AI 助手，附一句话：

按这份文档，帮我把备题达接到 WorkBuddy。令牌是 xxx，端口 47321。

文档里路径、字段、JSON 结构都写全了，它照着做即可。要它直接动手，把文件路径一起给它：

改 C:\Users\<用户名>\.workbuddy\mcp.json，按文档 7.4 的 WorkBuddy 那节加 petita。

改完自己确认三件事：

  1. 备题达「设置 → MCP」里出现「1 个客户端在线」
  2. 客户端那边能看到 petita 的工具列表
  3. 让它跑一次 bank_stats，能返回题库数字

三件都成就算通了，不成看 7.7。

7.7 报错与排查

按顺序查五项：应用是否在跑 → 端口是否一致 → 令牌是否完整 → 传输类型是否为 http → 面板里是否出现该客户端。

面板上的「测试连接」会实跑一次工具列表，返回「连接正常，返回 23 个工具」说明服务侧无问题。

现象 原因 处理
401 缺少或错误的访问令牌 令牌没带或不对 复制面板上的完整地址
404 路径写错 结尾应为 /mcp
「备题达没有在运行」 应用或窗口关了 打开应用
「工具执行超时（30 秒）」 页面卡住 切到应用窗口，等界面恢复
工具列表为空 握手未完成 重启客户端
只有部分工具 客户端缓存旧列表 断开重连

端口冲突：netstat -ano | findstr :47321 查占用，面板换端口后重启客户端。

十、已知限制

  • 仅 Windows 桌面版。移动端、网页版未提供。
  • 数据只在本机，不支持多设备同步或共享题库。
  • 单一数据库：一次只能打开一个数据目录，不做多库切换。
  • 通用版零预置数据，题库与教学内容需自行导入。
  • 无代码签名，首次运行 Windows 可能提示「未知发布者」。
  • AI 输出质量取决于所接模型，工具只负责把上下文喂准。
