一、MCP 是什么

1.1 一句话

MCP 是一套让 AI 客户端调用外部程序的协议。备题达内置了一台 MCP 服务器，把工作空间里的数据和方法暴露出去，你的 AI 客户端连上来，就能像人点界面一样读到真实数据、也能写入。

1.2 和「填个 API Key」不一样在哪

填 API Key 的模式是：你把题目复制给 AI，AI 回答完，你再手动贴回去。数据始终在你和 AI 之间的剪贴板里来回。

MCP 换了方向。AI 直接读你的题库，直接往选题车放题，直接往记忆模块加卡片。它拿到的不是截断的摘要，是你库里那一条真实记录。

API Key 模式 MCP
数据来源 你粘贴过去的文本 库里的原始记录
回答依据 你贴了多少它看多少 按需检索，可翻页
写回 手动复制 直接落库（受开关控制）
维护 每换一个客户端重配一次 配一次，换客户端只改地址

1.3 一个前提

备题达必须开着。数据在应用的本地存储里，MCP 服务只负责转发请求，真正干活的是那个已经打开的窗口。

窗口关掉，客户端会收到「备题达没有在运行」。这是设计如此，不是故障。

二、开启与鉴权

2.1 三步开启

  1. 打开备题达，进「设置 → MCP」。
  2. 确认面板顶部显示服务运行中。默认随应用启动，不用手动开。
  3. 复制「带令牌的地址」，粘到你的 AI 客户端里。

默认地址是 http://127.0.0.1:47321/mcp。端口可在面板里改，改完点保存，地址会跟着变。

2.2 地址、令牌、端口

名称 是什么 在哪看
地址 http://127.0.0.1:47321/mcp 面板第二行
令牌 32 位十六进制随机串 面板第三行，可单独复制
端口 默认 47321 面板输入框

令牌可以放在两处，效果一样：

http://127.0.0.1:47321/mcp?token=你的令牌

Authorization: Bearer 你的令牌

面板上「带令牌的地址」已经把令牌拼好了，直接复制最省事。只有 /health 不校验令牌，方便你确认服务活着。

2.3 写操作开关

面板上有一个「允许 AI 直接写入（跳过确认）」的勾选框。默认关。

关着的时候，AI 的写请求不会落库，而是在窗口里出一张待确认卡片，写好「要做什么、改哪条」，你点「执行」才真正写入。

打开之后，写请求直接执行，不再弹卡片。写错了按 Ctrl+Z 撤销，行为跟你在界面里手点一样。

建议：日常先关着跑一两周，看清楚 AI 会往库里写什么，再决定要不要打开。

2.4 重置令牌

面板上有「重新生成令牌」。点之前会让你确认一次。

重置后旧令牌立刻失效，所有连着的老客户端会断开，需要用新地址重连。怀疑令牌泄露时用这个。

2.5 端口被占用

改端口即可。保存后服务自动重启，地址和令牌不变。

如果改了端口客户端连不上，先看客户端里填的是不是旧端口。面板上的「测试连接」会实跑一次工具列表，返回「连接正常，返回 20 个工具」就说明这一侧没问题。

三、各模块怎么用

这一章按模块讲。每个模块给三样东西：对应哪些工具、怎么用自然语言问、返回什么要注意。

不用背工具名。把意图说清楚，客户端会自己挑工具。

3.1 题库检索

工具 作用 关键参数
bank_search 按条件检索题目，返回 ref 与摘要 kw 关键词、points 知识点、qtype 题型、difficulty 易/中/难、lesson 关联篇名、limit 条数
bank_stats 题库总量、题型分布、知识点分布 无

问法示例：

  • 「找 3 道考『虚实结合』的题，中等难度」
  • 「语文题库里一共多少题，简答题占多少」
  • 「跟《登高》有关的题，先给我 10 道的题干」

limit 默认 8，最多 24。要更多就分批，或者把条件收紧。一次要 50 条大概率被截断，AI 也可能自己编后面的。

bank_search 返回的是摘要加 ref，不是完整题目。摘要里的题干是截断的，看着眼熟不等于就是你要的那道。要正文得用 question_get。

bank_stats 适合开场。先问家底，再决定检索条件，比直接瞎搜省事。

3.2 单题与试卷

工具 作用 关键参数
question_get 取一道题的完整内容：题干、选项、答案、解析 ref：题目引用，形如 gk2019-qg1\|s1\|0
paper_list 列出已有试卷 keyword

ref 是题目的唯一坐标，来自 bank_search 的返回值。它长得像 gk2019-qg1|s1|0，竖线是分隔符，别手改。

问法示例：

  • 「把第一道题的答案和解析给我」
  • 「这几道题里哪几道有解析」
  • 「我库里有几套完整的卷子，按年份列一下」

先搜再取，不要一上来就要「把所有题的解析给我」。一次取一道，AI 反而答得准。

question_get 返回的内容包含答案。如果你在让学生用这套东西，注意别把带答案的输出直接投屏。

3.3 篇目与单元

语文线预置了五册篇目与教参原文，lesson_get 和 unit_get 取的就是这批数据。

工具 作用 关键参数
lesson_get 按篇名取原文、注释、要点 title：篇名，如 登高
unit_get 按册次取单元结构 volume：册次，如 必修上；keyword：单元关键词

问法示例：

  • 「把《登高》的原文、注释和要点取出来，按两课时拆一下」
  • 「必修上第三单元有哪几篇，各自的人文主题是什么」
  • 「《劝学》里『而』的几种用法，按例句归类」

lesson_get 认的是篇名，不是文件名。篇名对不上会返回空，先把书名号去掉再试，比如问「登高」而不是「《登高》」。

unit_get 的 volume 要按库里实际叫法写。不确定就先问「有哪些册次」，让它把 unit_get 不带参数跑一次，看返回值里的册次列表。

3.4 选题车（组卷）

工具 作用 关键参数
cart_get 取当前选题车里的题目 无
cart_add 把题加进选题车（写） refs：ref 数组
cart_remove 从选题车移除（写） refs：ref 数组

选题车就是界面上正在组的那份卷子。AI 往里加题，你切回窗口就能看到，版式和手动添加的一样。

问法示例：

  • 「把刚才那 5 道题放进选题车」
  • 「选题车里现在有哪些题，按题型归类」
  • 「把第三道删掉，换成一道难的」

cart_add 需要的是 ref 数组，不是题干文本。所以流程永远是：先 bank_search 拿到 ref，再 cart_add。中间跳一步就会失败。

加了不想要，直接说「撤销」或「移出第三题」。写操作都留了撤销记录。

3.5 记忆模块

工具 作用 关键参数
memory_list 列出分类与卡片，可按分类过滤、只看待复习 group 分类、due 只看今日待复习
memory_add 新增一张卡片（写） front 正面、back 背面、group 分类

记忆模块用的是间隔复习。答对升一级，间隔拉长；答错退回第一天，重新来。

问法示例：

  • 「今天该复习的卡片有哪些」
  • 「把这段文言实词做成卡片，正面写词、背面写释义和例句，放进『文言实词』分类」
  • 「『文言实词』这个分类现在有多少张卡，掌握到什么程度」

memory_add 一次加一张。批量加要说「一张一张加」，或者直接给一批数据让它循环。一次塞 50 张进去，失败率会高。

分类名要和界面上现有的对齐。写了个新分类，memory_list 按旧分类过滤时看不到它，不是丢了。

3.6 学情与卷头

工具 作用 关键参数
progress_get 教学进度与课时安排 class：班级
profile_get 卷头信息：学校、学科、年级、班级、学期 无

profile_get 返回的是你在设置里填的卷头，出卷时直接套用。改卷头在界面里改，改完 MCP 读到的就是新的。

问法示例：

  • 「按高一(3)班的进度，下周该讲到哪了」
  • 「现在卷头填的是什么，学期对不对」
  • 「这个班还剩几课时，够不够讲完这个单元」

progress_get 需要班级名，得和界面里建的对上。名字不对就返回空，先问一句「有哪些班级」更稳。

3.7 校历

工具 作用 关键参数
calendar_get 校历：班级、节次、课表、日程事件 from / to：日期范围
event_add 加一条日程（写） date 日期、title 标题、type 类型、note 备注

问法示例：

  • 「查下周的课表和日程」
  • 「下周三加一条『月考讲评』，类型是考试」
  • 「这个月有几节连堂课」

日期格式用 2026-11-18。含糊的「下周三」也能用，AI 会换算，但跨月、跨学期时容易算错，重要的日程直接写死日期。

event_add 的 type 决定它在校历上的颜色与分组，和界面里手动添加是同一套取值。

3.8 教学偏好

工具 作用 关键参数
pref_append 往教学偏好里追加一条（写） text：偏好内容

教学偏好是一组长期生效的约定，AI 每次干活前会读。写进去的东西会一直影响输出。

问法示例：

  • 「记一下：出选择题一律四个选项，不要五个」
  • 「记一下：解析要写踩分点，按点给分」
  • 「记一下：默写只考课标 60 篇，超纲的不要出」

偏好是追加，不是覆盖。写重了会同时存在两条，结论看哪条看 AI 判断。写之前先用 pref_append 的返回值或界面确认现有内容。

3.9 ima 知识库

工具 作用 关键参数
ima_search 在 ima 知识库里检索 kw
ima_list 列出条目 limit
ima_read 读某条资料的全文 id
ima_import_paper 把一份试卷导入题库（写） id

前提是先在设置里配好 ima 的凭据。没配的话这四个工具会返回凭据错误，其他工具不受影响。

问法示例：

  • 「在 ima 里找去年的一模卷」
  • 「把这份卷子的第 3 题原文读出来」
  • 「把这份卷子导入题库，题型按选择题处理」

ima_import_paper 是写操作，会往题库里真正加数据。导入前先 ima_read 看一眼结构，别把整本资料当试卷导进去。

四、接各类客户端

配置格式各家不一样，但填的东西只有两个：地址和令牌。下面按客户端给。

4.1 Claude Desktop

配置文件在 %APPDATA%\Claude\claude_desktop_config.json。没有就新建。

{
  "mcpServers": {
    "petita": {
      "type": "http",
      "url": "http://127.0.0.1:47321/mcp?token=你的令牌"
    }
  }
}

保存后完全退出 Claude Desktop（托盘里也要退），再启动。设置里能看到 petita 和 20 个工具，就是连上了。

4.2 Cursor

项目级配置放 <项目>/.cursor/mcp.json，全局放 ~/.cursor/mcp.json，格式和上面一样。

Cursor 的设置里有一页 MCP，能看到每个服务器的状态点。绿点表示连上，红了点开看错误。

4.3 VS Code（GitHub Copilot Chat）

在 .vscode/mcp.json 里写：

{
  "servers": {
    "petita": {
      "type": "http",
      "url": "http://127.0.0.1:47321/mcp?token=你的令牌"
    }
  }
}

Copilot Chat 里切到 Agent 模式，输入框下方的工具图标里能看到 petita 的工具。

4.4 Claude Code

claude mcp add --transport http petita "http://127.0.0.1:47321/mcp?token=你的令牌"

加完用 claude mcp list 确认。要在某个项目里用，加 --scope project。

4.5 Cherry Studio

设置 → MCP 服务器 → 添加。类型选 streamableHttp，URL 填带令牌的地址。保存后点测试。

4.6 Cline

Cline 的设置里有 MCP Servers，选「Remote Servers」，填名称和 URL。Cline 只认 http 类型，不要填成 stdio。

4.7 Continue

~/.continue/config.json 里：

{
  "mcpServers": [
    {
      "name": "petita",
      "transport": { "type": "http", "url": "http://127.0.0.1:47321/mcp?token=你的令牌" }
    }
  ]
}

4.8 自建平台（Open WebUI、LibreChat 等）

这类平台自己实现了 MCP 客户端，配置项名称各异，核心还是 URL。有的要求把令牌单独填进 Header，那就填 Authorization: Bearer 你的令牌，URL 里的 ?token= 去掉。

平台的 MCP 支持程度差别很大。能配 HTTP 型的 device 直接填；只能配命令行的走 4.9。

4.9 只支持命令行的客户端

有的客户端只接受 stdio（启动一个本地进程来通信）。备题达是 HTTP 服务，中间需要一个转换脚本。

#!/usr/bin/env node
// stdio → HTTP 桥：把客户端的 stdin/stdout 转发到备题达的 HTTP 端点
const readline = require("readline");

const URL = process.env.PETITA_URL || "http://127.0.0.1:47321/mcp?token=你的令牌";
const rl = readline.createInterface({ input: process.stdin });

rl.on("line", async (line) => {
  if (!line.trim()) return;
  try {
    const res = await fetch(URL, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: line,
    });
    process.stdout.write((await res.text()).trim() + "\n");
  } catch (e) {
    process.stdout.write(
      JSON.stringify({ jsonrpc: "2.0", id: null, error: { code: -32000, message: String(e) } }) + "\n"
    );
  }
});

存成 petita-bridge.js，客户端配置里把 command 指向 node，参数填这个文件的路径。

这个桥只处理一行一条消息的简单场景。客户端如果要服务端主动推送（SSE），得自己补。

4.10 自己写 agent

不需要任何 SDK，直接用 HTTP。三个步骤：握手、列工具、调工具。

BASE="http://127.0.0.1:47321/mcp?token=你的令牌"

# 1) 握手
curl -s "$BASE" -H "Content-Type: application/json"   -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"my-agent","version":"0.1"}}}'

# 2) 看有哪些工具
curl -s "$BASE" -H "Content-Type: application/json"   -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'

# 3) 调一个工具
curl -s "$BASE" -H "Content-Type: application/json"   -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"bank_stats","arguments":{}}}'

Python 版本：

import requests

BASE = "http://127.0.0.1:47321/mcp?token=你的令牌"
H = {"Content-Type": "application/json"}

def rpc(method, params=None, _id=1):
    body = {"jsonrpc": "2.0", "id": _id, "method": method}
    if params is not None:
        body["params"] = params
    return requests.post(BASE, json=body, headers=H, timeout=60).json()

rpc("initialize", {"protocolVersion": "2025-06-18", "capabilities": {},
                   "clientInfo": {"name": "my-agent", "version": "0.1"}})
tools = rpc("tools/list", _id=2)["result"]["tools"]
print(len(tools), "个工具")

hit = rpc("tools/call", {"name": "bank_search",
                         "arguments": {"kw": "虚实结合", "limit": 3}}, _id=3)
print(hit["result"])

initialize 必须第一个发。之后每次请求都是一个独立的 HTTP POST，没有会话 cookie。

五、三个真实流程

流程一：从检索到成卷

问：找 5 道考『虚实结合』的题，中等难度
→ bank_search 返回 5 条 ref 和摘要
问：第二道和第四道换成难一点的
→ bank_search 再跑一次，条件加上 difficulty=难
问：把这 5 道放进选题车
→ cart_add 写入，切回窗口就能看到卷子在长

关键点：全程不复制题干。AI 靠 ref 操作，错不了位。

流程二：把一次听课笔记变成卡片

问：把下面这段整理成背诵卡片，一张一问，正面写问题、背面写答案，放进『文言实词』分类
（贴一段笔记）
→ memory_add 逐张写入
问：这个分类现在有多少张，今天该复习几张
→ memory_list 按分类和待复习过滤

写卡片前先确认分类名存在。新分类第一次写会建，但界面上的筛选是另一套逻辑，容易看着像没写进去。

流程三：按进度排下周

问：高一(3)班现在讲到哪了，剩几个课时
→ progress_get
问：下周的课表是什么
→ calendar_get
问：按这个进度，下周的课帮我排一下，写到校历里
→ event_add 逐条写入（写开关关着时会出待确认卡片）

排课这种一次写多条的操作，建议关着写开关跑，逐条确认比批量翻车强。

六、安全边界

6.1 数据不出本机

服务只监听 127.0.0.1。局域网里的其他机器、公网都连不进来。

数据一直在你本地的应用存储里，MCP 只做转发，没有云端副本，也没有账号体系。

6.2 令牌挡的是什么

挡的是同一台机器上的其他程序。没有令牌，本机的任何进程都能调你的题库，包括你不认识的那些。

令牌泄露的后果是：那个程序能读你的全部数据，写开关打开时还能写。所以不要在截图、日志、公开仓库里带令牌。

6.3 写操作的边界

写工具只有 6 个：cart_add、cart_remove、event_add、memory_add、pref_append，ima_import_paper。读工具不受开关影响。

写开关关着时，写请求变成待确认卡片，不落库。打开后直接执行，可 Ctrl+Z 撤销。

6.4 应用关了就断了

MCP 服务跟着应用进程走。应用退出，端口关闭，客户端立刻失效。

这不是缺陷。备题达是桌面应用，数据在窗口里，窗口不在，服务也没有意义。

七、排错

7.1 连不上，按这个顺序查

  1. 应用开着吗？面板显示「服务运行中」吗？
  2. 地址的端口和面板上的一致吗？
  3. 令牌复制完整了吗？有没有多空格、少一位？
  4. 客户端的传输类型选对了吗？备题达是 http，不是 stdio。
  5. 面板上「N 个客户端在线」有没有出现你的客户端？

前四条都对还连不上，在面板点「测试连接」。它返回「连接正常」说明服务这侧没问题，问题在客户端配置。

7.2 常见报错

现象 原因 处理
401 缺少或错误的访问令牌 令牌没带或不对 复制面板上的完整地址
404 地址路径写错 确认结尾是 /mcp
「备题达没有在运行」 应用关了或窗口关了 打开应用
「工具执行超时（30 秒）」 页面卡住或没响应 切到应用窗口，等界面恢复再试
工具列表是空的 客户端没走完握手 重启客户端
只有部分工具 客户端缓存了旧的工具列表 断开重连

7.3 端口冲突

# 看谁占了 47321
netstat -ano | findstr :47321

在面板里换个端口（比如 47322），保存后重启客户端，用新地址。

八、常见问题

要不要联网？ 不要。整个链路在本机完成。

能不能多台电脑共用一个题库？ 不能。数据在本机，MCP 也只监听本机。

AI 会不会把我的库改坏？ 写开关关着时不会，只有你点了「执行」才写。打开后能改，但每次写都留撤销记录。

能不能同时连多个客户端？ 能。面板会列出每个客户端和它的调用次数。

令牌多久换一次？ 没有强制周期。怀疑泄露时重置一次即可。

附录 B：协议细节

写自己的客户端时看这一节。

  • 传输：HTTP POST，JSON-RPC 2.0，单条请求单条响应，不做 SSE 流。
  • 协议版本：2025-06-18。
  • 端点：POST /mcp（业务）、GET /health（健康检查，免令牌）。
  • 鉴权：?token= 查询参数或 Authorization: Bearer 头，二选一。
  • 握手：initialize → 客户端发 notifications/initialized → tools/list → tools/call。

tools/call 的返回结构：

{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [{ "type": "text", "text": "…" }],
    "isError": false
  }
}

写开关关着时，写工具的返回不是报错，而是：

{
  "result": {
    "content": [{ "type": "text", "text": "已生成待确认的操作：…请在备题达窗口里点「执行」。" }],
    "isError": false
  }
}

客户端要能识别这种「pending」语义，否则会以为写成功了。

附录 C：命令行自检

出问题时，先用 curl 排除服务端。

# 服务活着吗（免令牌）
curl -s http://127.0.0.1:47321/health

# 令牌对吗（应返回工具列表）
curl -s "http://127.0.0.1:47321/mcp?token=你的令牌"   -H "Content-Type: application/json"   -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# 调一个不写库的工具
curl -s "http://127.0.0.1:47321/mcp?token=你的令牌"   -H "Content-Type: application/json"   -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"bank_stats","arguments":{}}}'

/health 返回 {"ok":true,...} 说明服务在跑。带着令牌能拿到 tools/list，说明鉴权和协议都通。剩下就是客户端那一侧的事。
